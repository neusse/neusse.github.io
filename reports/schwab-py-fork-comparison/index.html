Schwab-py fork comparison

Reviewed: 2026-11-02
Scope: Public GitHub source, project metadata, commit ancestry, releases, tests, docs, and local package/plugin compatibility checks. No live Schwab API calls were performed. Commit counts below come from cloning each public main ref and comparing its Git history to alexgolec/schwab-py main on the review date.

Recommendation

For schwab-pi, Yoshishima is the best starting point if the plugin can require Python 3.12+: it preserves the schwab import and schwab-py distribution, stays on the original project's Git history, has cross-platform CI, and carries a focused set of security, order, streaming, and query fixes. Pin an exact commit and resolve its release-version mismatch before relying on it: the checkout and latest GitHub Release are tagged v1.7.3, while schwab/version.py and the README still identify 1.7.2.

If the immediate problem is specifically Authlib 1.8's switch from httpx to httpx2, Jubishop is a narrow compatibility patch; consider backporting the change rather than treating this one-commit fork as a maintained replacement. Hu1kSmash's schwaby is the most active and substantially developed alternative, with a separate package name and release line. It should be evaluated as a migration or side-by-side pilot, not swapped into code importing schwab without changes.

Per-fork assessment

Jubishop

The fork's single commit is explicitly a fix for upstream issue #268: Authlib 1.8 now builds OAuth clients on httpx2, so Schwab's own requests, exception handling, and OAuth response types need to use the same HTTP library. The commit updates Authlib and HTTP dependencies, replaces httpx imports/checks with httpx2, updates docs and tests, and states that exposed responses/errors become httpx2 types. It changes 17 files but remains only one commit past upstream. (commit)

The distribution and import names remain compatible with existing schwab-py use, and its Python floor remains 3.10. However, the package version remains the inherited 1.5.1 and setup.py still identifies the upstream project for source/issues. This is useful as a patch reference; it provides little evidence of a separate long-term release or maintenance plan. Because HTTP responses and exceptions become httpx2 classes, callers that type-check against httpx.Response or its exceptions still need review.

Yoshishima

This is the closest maintained continuation of upstream: its history descends from the same 43c4614 baseline and adds 39 commits. Its README lists callback/OAuth robustness, safer token writes, more robust stream dispatch, Decimal-based price calculations, and query validation. The source history includes migrations to httpx2, Decimal price fixes, and token/logging hardening; the latest commit covers refresh-token handling and sensitive-data redaction. (README, httpx2 migration, Decimal price fix, latest security commit)

The repo retains import schwab and the schwab-py distribution, and tells users to install from its GitHub URL because PyPI and Read the Docs remain upstream-maintained. Its CI runs Python 3.12, 3.13, and 3.14 on all three major desktop/server OS families. The decisive compatibility cost is its python_requires='>=3.12'; it also changes the raw HTTP response type to httpx2, raises dependency minimums, and tightens some inputs/behavior. (setup.py, CI workflow)

There is a release identity discrepancy to resolve before pinning by tag: the Git checkout's HEAD and latest GitHub Release are tagged v1.7.3, but schwab/version.py and README say 1.7.2. Pinning the full commit SHA avoids ambiguity while the maintainer clarifies the release. (version file, releases)

Hu1kSmash / schwaby

This has become a separate project, not a branch that can be merged from the original's Git history. Its changelog says it began from schwab-py and has been a separate project since 2.2.0; its README describes the reasons and retained MIT licensing/attribution. It has its own 5.x release line, current changelog, and ongoing commits. (README, changelog, releases)

The most significant migration change is intentional: both the installed distribution and package import are schwaby, so it can coexist with schwab-py but existing from schwab ... imports must be rewritten. The project retains Python >=3.10, uses httpx2/Authlib >=1.8, and documents broader fixes around exact order prices, token-file safety, streaming errors/lifecycle, and validation. Its CI covers Python 3.10–3.14, with Linux on each push, all three OSes on pull requests/tags/manual runs, and a weekly fresh dependency-resolution job. (setup.py, tests workflow, fresh-resolve workflow)

The project's source and test surface is much larger than the upstream-based fork's. That is evidence of active maintenance, but also means the API and behavior should be treated as its own product. Its README explicitly warns users that the library places real orders and its changelog records behavior and security changes; for an existing plugin, first test it side-by-side and reconcile one or two paper/live-disabled test paths before considering migration.

Upstream signals and migration checks

The original repo has open reports for the Authlib/httpx2 transition (#268), float truncation lowering some prices by a cent (#239), stream requests that can wait forever (#237), missing stream shutdown (#235), and token-file permissions/atomicity (#231). These are reports, not independent reproductions in this review; check their current status and reproduce against the plugin's locked dependency set before treating them as confirmed in your deployment.

For either schwab-py fork, check these before changing the plugin lock:

  1. The plugin's runtime must meet the fork's Python floor. Yoshishima requires 3.12; Jubishop and schwaby allow 3.10.
  2. Search for assumptions about httpx.Response/httpx exceptions. The forks using Authlib 1.8 expose httpx2 response/error types.
  3. Exercise auth refresh and token-file handling; order construction and price serialization; stream subscription, timeout, handler failure, and shutdown; and the plugin's error/status-code handling.
  4. Pin an immutable commit or verified tag. This matters especially for Yoshishima's tag/version mismatch and for GitHub-installed versions that are not the upstream PyPI release.
  5. If staying on upstream, the Jubishop change is the smallest reference implementation for the Authlib/httpx2 transition. If moving to a more fully maintained upstream-compatible line, compare the exact Yoshishima diff against the plugin's dependency policy before adopting it.

Local compatibility evidence

Local checks used Python 3.13.13 in isolated virtual environments:

  • The current schwab-pi suite passed all 23 tests against the original checkout, Jubishop, and Yoshishima. Those tests mainly verify the plugin's wrappers and mocks; they do not fully exercise real HTTP response classes.
  • Jubishop's own suite passed 677 tests locally. Its fork does not currently publish releases or run Actions on its own repository, so this local result is the main execution evidence beyond its upstream pull request.
  • A targeted Yoshishima check confirmed that an HTTP 429 raises httpx2.HTTPStatusError. The plugin's current response_json() catches httpx.HTTPStatusError, so its custom 429 guidance is skipped. This needs a plugin change for Yoshishima, Jubishop, or schwaby despite the 23 wrapper tests passing.
  • Hu1kSmash cannot be dropped into the current test environment unchanged because the plugin imports schwab.* while the project intentionally exports schwaby.*. Its public CI was green at the reviewed main commit, including the scheduled fresh-dependency-resolution workflow.
